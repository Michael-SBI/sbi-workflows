Project Setup — Won Deal → Live Project

What happens the moment a sales deal is won: the one thing that's automatic, and the setup chain the team runs by hand in Claude Desktop.

The model in one line

When a deal hits Closed Won, the project folder is created automatically — and that's the only automatic step. Everything after that (handover, budget, procurement, RFQs, site works, dashboard) is run by hand, one skill at a time, in Claude Desktop (Cowork), alongside the day's work.

There is no orchestrator any more. Both the old Make-triggered automation and the coordinator that chained the steps together are retired — the team now runs each of the six setup skills individually. That's deliberate: every step is seen and confirmed before the next, so nothing lands wrong on a live folder.

1

The trigger — automatic on Won

Make.com webhook

Make scenario 5232361 ("SBI Project Setup — Folder v3") watches the Deals list. The instant a deal moves to Closed Won, it creates the project folder from the ClickUp folder template t-90161746266, named {jobNo} {Client} - {Suburb}. It posts a non-blocking comment if key fields are missing.

That is all Make does. It does not rename the folder, populate tasks, or run any sub-skill — the datastore/queue and orchestrator-trigger modules were stripped out when the automated chain was retired. The folder just appears, ready for the team to set up.

2

The six setup steps — run by hand in Cowork

▶ How it's run: the team works in Claude Desktop (Cowork) split-screen — Claude on one side, ClickUp on the other — and runs the six setup skills below individually, in order, kicking off the next only once the last is done and checked. Each skill is called on its own (e.g. /sales-handover {job}, then /budget-cost-sheet {job}, …) — no orchestrator chains them. Some steps are skipped by job type (see the flags). Tap any step to expand.
1
Sales Handover
/sales-handover

Turns the fresh empty folder into a populated project. This is the seam between Sales and Projects.

  • Rename the SOLD … placeholder; multi-list the won sales task into List 01 Sales File Info
  • Copy the approved proposal, plans, Buildsoft link, deal value and client details across
  • Create the ✨️12 SBI PROJECT DOC from scratch, born correctly named, with its 6 standard pages (the template no longer ships the Doc)
  • Set the progress-claim split by job type (Standard 40/30/20/10 · Joinery/Design 60/40 · Residential 10/40/50)
  • Create the project Chat channel; close the won deal's leftover sales subtasks; post the handover comment tagging Michael/Gail/Leah
2
Budget Cost Sheet
/budget-cost-sheet
BUILD + Buildsoft

Reads the raw Buildsoft export and builds the SBI Cost Budget — a formatted Excel tab plus a styled PDF with Cost-Breakdown and Sales-Breakdown donut charts.

  • Pre-flight validates real Qty / Rate / Total values exist before running
  • Cost Sheet Detail + Summary tables, all cost-code categories
  • Footer totals: Cost · Markup · Overhead · Profit · Sell incl-GST, cross-checked against deal value
  • Skipped for design-only / supply-only jobs with no Buildsoft build pricing
3
Procurement Setup
/budget-to-procurement

Reads the cost basis per cost code (straight from the raw Buildsoft export) and creates one procurement task per category in List 08 Procurement_Budget track, with the ex-margin budget set on each.

  • One task per cost-code category — e.g. 310 {Job} BUILD Materials
  • Budget amount set on each task so the PM tracks spend vs budget
  • Re-runs match by cost-code number and update in place — no duplicates
  • PM then progresses the workflow: Not Started → Quoting → Ordered → Received
4
RFQ — Contractors & Suppliers
/SBI-RFQ-Contractors-Suppliers

Makes the procurement tasks RFQ-ready so quotes can go out.

  • Links the top 3 matching subcontractors/suppliers from the Contractors & Suppliers list to each in-scope task
  • Writes a ready-to-send scope-of-works into each task description
  • Creates one RFQ {sub name} tracking subtask per matched sub
  • Standing subs are always included per trade (TCA Electrical, Brush Magic)
5
Site Works Tasks
/site-works-tasks
Skippable

Creates the on-site install/measure subtasks under 10.1 SITE WORKS [SCHEDULE] in List 10 Site Works, built from the signed proposal scope.

  • One subtask per on-site activity (measure, install, fit-off) from the scope
  • Shows a plan before writing anything
  • Skipped when the scope has no on-site work — supply-only joinery, design-only, or factory-only jobs
6
Audit + Dashboard
/handover-audit · /project-dashboard

Verifies the setup, then publishes the live project view.

  • handover-audit — compares the folder against what a fresh setup produces, and reports every gap (missing tasks, blank fields, stale data) so they can be fixed
  • project-dashboard — generates the interactive HTML dashboard (overview, financials, procurement, schedule, compliance, actions) and deploys it to michael-sbi.github.io/sbi-dashboards/{slug}/
  • Posts one summary comment on the project tagging the owners

What a live project folder holds

4

Re-run safety

Each skill is safe to re-run on an existing project — they read PM-owned state as-is and write only in narrow, well-defined places. They never recreate or overwrite existing site-works or tasks.

✓ Reads as-is (never touches)

  • Existing site-works subtasks
  • Task statuses, comments, dates
  • PM-entered schedule + claims
  • Anything a human has edited

✎ Only writes

  • Missing folder/list fields from sales
  • New procurement tasks (matched by cost code, updated in place)
  • The dashboard HTML (regenerated)
  • The summary comment

C · Whiteboard — the rules

  • Created by a person on the P2 Package-up subtask — doesn't come through the template
  • Sheets dragged in from the G: folder; photo numbers ①②③ match the plan
  • Michael reviews the red Discussion points and pens before anyone else starts
  • P3 Distribute sends the board link; the drawer works off it
  • No API — that's why the script stops at sheets

The three handoffs — same pattern every time

Collect everything into one place → a person reviews and pens the mark-up on a whiteboard → the receiver works off the board. The skill collects; the judgement stays with the person. H1 is built and running; H2 and H3 are the same pattern at CLOSED WON and are proposed here for review — nothing is built for them yet.

The phases — tap to open, tap a step for in / out

P1 — Engagement

inquiries recieved → active outreach → qualified lead
Owner Gail · target ≤10 days in phase · exit: plans/scope in hand and a meeting booked
  1. SETUP — acknowledge, name the deal, contact details Gail≤1 hr
    First contact sets the pace. Acknowledgement email the same hour; the contact-details checklist on the task can't be left with a box unticked. Job Type and the joinery checkbox decide the P3 tracks later — set them now. Once qualified, rename to TS{YYMMDD} {Surname} — {Type} and make the Drive folder from the template.
    In
    • Web enquiry (ClickBot) or a logged call
    • ClickUp automation sets start_date
    Out → where
    • 🤝 01/02/011/05, 🤝 21, Joinery? → A fields
    • Ack email → A Sales Correspondence
    • Deal renamed TS… → A
    • Job folder created → B (by hand; the skill backfills if missed)
  2. Phone call + email — project info and intro meeting requested Gail≤1 day
    Call first, then email. The call qualifies (space, scope, plans, timing, budget); the email is Gail's standard "in order of usefulness" list — plans, mark-up, photos of existing, look-and-feel — with the online-meeting booking link. Online is the default; a site visit only when the job needs it.
    In
    • Contact fields from 1.1
    Out → where
    • Call notes → A 🤝 20 NOTES DURING SALES PROCESS
    • Status → active outreach
    • Email + booking link → Sales Correspondence
  3. Project information received — the waiting item, with 3 follow-ups + polite close Gail3 days, then ~2–3 each
    Chain: 1.3a Follow-up #1 (nudge) → 1.3b #2 (offer the meeting instead of plans, by phone) → 1.3c #3 (name a date) → 1.3d Send polite closing email → status declined_no proposal. Draft wording is in each subtask's description. Nothing closes the follow-ups for you — close them by hand when the info lands.
    In
    • Client plans, photos, scope by email
    Out → where
    • Plans → B 4.0 PLANS (or attached to the deal — the skill sweeps them)
    • Link → A table row 2.1 Client supplied Plans/Docs
    • Status → qualified lead
    • Or terminal: declined_no proposal, reason in 🤝 20
  4. Introductory meeting invite, with 3 follow-ups Gail~2–3 days each
    Runs in parallel with 1.3. #1 offers two specific times, #2 is a phone call, #3 names a date. No separate closing email — the chain lapses to 1.3d. Booked = calendar invite to the client and Michael.
    In
    • Booking link from 1.2
    Out → where
    • Status → initial meeting booked
    • Meeting in Michael's calendar (Meet or site)

Off-ramps and terminals

statuses
The parent status is the stage. These keep the pipeline and the dashboard honest.
  1. on hold drip feed — they need time. start_date = the re-contact date (the snapshot shows "re-contact ~date", never a negative age).
  2. client ghosting — silence after a chase chain. Later → done lost after proposal.
  3. declined_no proposal — fell out before pricing (P1 chain exhausted, wrong job type). No estimating spent.
  4. done lost after proposal — priced and presented, lost.
  5. re-price proposal → re-open only the P3 tracks the change touches → Qwilr → Meeting Ready → re-present proposal → re-open the P4 items → contracts requested on yes. No P6/P7 containers.
